# S00 — Репозиторий, окружение, хостинг, Битрикс

## Цель

Понять, из чего состоит текущий сайт и где он работает. Закрыть G-HOST и G-BX из ARCHITECTURE.md §10.

## Доступ к БД

Параметры — в `.phase/env`. Только SELECT (`b_module`, `b_site_template`, `b_agent`, `b_lang`).

## Что выяснить

Каждый пункт — с доказательством: путь к файлу, команда и её вывод, SQL и результат.

1. Структура репозитория: что под git, что нет (`upload/`, `bitrix/`), размер.
2. Версия ядра Битрикса (`bitrix/modules/main/classes/general/version.php`), редакция, установленные модули (`b_module`). Есть ли `catalog`, `sale`, `search`, `seo`, `sprint.migration`, модули обмена с 1С.
3. Шаблоны сайта (`local/templates`, `bitrix/templates`), какой активен (`b_site_template`).
4. Свой код: `local/php_interface/init.php`, обработчики событий, `local/components`, `_ajax`-подобные скрипты, агенты (`b_agent`).
5. Интеграции: 1С (`/bitrix/admin/1c_exchange.php`, настройки), платёжные системы, доставки, внешние API, почтовые шаблоны.
6. Хостинг прода: ОС, веб-сервер (nginx/apache), версия PHP, есть ли Node и можно ли держать процесс (pm2/systemd/supervisor). Если данных нет в репозитории — вопрос Николаю, не догадка.
7. Мультисайтовость, поддомены, `b_lang`.

## Вне этапа

- Никаких изменений в коде и БД. Ядро `bitrix/` читать только для версии и списка модулей.
- Не проектировать решение.
