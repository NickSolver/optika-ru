# optika-lokamed.ru — архитектура (черновик заморозки)

Статус: DRAFT. Разделы с пометкой GATE закрываются после S00–S02 (исходники, дамп БД).

| # | Решение | Кем |

## 2. Схема запроса

```
Браузер ─GET /catalog/opravy/─▶ nginx ─▶ Bitrix
  urlrewrite ─▶ /catalog/index.php
    └─ lokamed:page (class.php)
        1. Resolver: путь ─▶ раздел | товар | 404 | 301
        2. PageProvider[PAGE]: собирает props по белому списку
        3. LayoutProvider: меню, контакты, салоны подвала (кеш)
        4. $APPLICATION: title, description, canonical, robots
        5. SsrRenderer ─POST 127.0.0.1:3100/render─▶ Node
             {page, props, url, build} ◀─ {html, build}
        6. Вывод: <div id="app">HTML</div> + props + ассеты из manifest
Браузер: createSSRApp(App, props).mount('#app')  ─▶ гидрация
```

## 3. Контракт PHP → Node

Запрос `POST /render`, JSON:

```json
{ "page": "CatalogSection", "url": "/catalog/opravy/?page=2",
  "build": "a1b2c3", "props": { "layout": {}, "page": {} } }
```

Ответ `200`: `{ "html": "...", "build": "a1b2c3" }`.
Ответ `4xx/5xx`: `{ "error": "code" }`, без стека.

Правила:

- Node слушает только `127.0.0.1`. Наружу не открыт.
- Таймаут: connect 100 мс, total 500 мс.
- `build` в запросе и ответе должны совпасть. Не совпали (гонка при деплое) — рендер не принимается, работает запасной режим.
- Node не ходит в БД и в API. Всё, что нужно странице, приходит в props.
- На каждый запрос — новый `createSSRApp` и новый Pinia. Глобального состояния между запросами нет.

## 4. Запасной режим (Node недоступен)

- PHP отдаёт пустой `#app` + props + клиентский бандл. Страница рисуется в браузере.
- Пользователь страницу получает. Ответ 200, не 500.
- Пишется запись в лог `lokamed.ssr` + счётчик. Порог алерта — 5 сбоев за 5 минут.
- Это авария, а не штатный режим: боты в это время видят пустую страницу.

## 5. Кеш

| Уровень | Ключ | Инвалидация |
|---|---|---|
| Props страницы | страница + сущность + параметры запроса | теги инфоблоков (`iblock_id_N`) |
| Props layout | версия меню/контактов | теги инфоблоков меню и салонов |
| HTML рендера | `md5(page + json(props) + build)` | новый build; истекает по TTL 1 ч |

HTML зависит только от props и build. Поэтому кеш по хешу props безопасен: изменились данные → изменился хеш.

**В SSR и в кеш не попадает ничего пользовательского:** корзина, избранное, авторизация, просмотренные. Это грузится после гидрации запросом `GET session` и рисуется на клиенте. Иначе один пользователь увидит корзину другого из кеша.

## 6. Правила для Vue-кода (проверяются критиком)

- В `setup` и в шаблоне нет `window`, `document`, `localStorage`, `Date.now()`, `Math.random()`. Только в `onMounted`.
- Камера, карты, face-api — внутри `<ClientOnly>`.
- `v-html` — только для HTML-полей инфоблоков (контент администратора). Отзывы и прочий пользовательский ввод — только текстом.
- Props-типы описаны в `frontend/src/contracts/*.ts`. PHP-провайдер и TS-тип меняются в одном этапе.
- Цена отсутствует — это отдельное состояние, не `0`.

## 7. Безопасность

- Props — белый список полей. Сырые `PROPERTIES`, `~`-поля, служебные ID во фронт не уходят.
- Встраивание props в HTML: `JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT`.
- Цена, сумма заказа, скидка по промокоду — только с сервера. Клиент передаёт ID и количество.
- Изменяющие запросы API — POST + CSRF (`sessid`) + `ActionFilter\Csrf`.
- Формы: сначала запись в БД, потом уведомление. Сбой уведомления не превращает принятую заявку в ошибку.

## 9. Фильтр и URL

- Состояние фильтра — query-параметры. Любой URL фильтра отдаётся сервером целиком (SSR), не только через API.
- В браузере фильтр ходит в API и меняет URL через `history.pushState`.
- Комбинации фильтра не индексируются: `robots: noindex, follow`, canonical на раздел. Требует подтверждения (G1).
- Старые URL фильтра и страниц — карта 301 по итогам S02.

## 10. GATE — закрываются после получения исходников

| Gate | Что узнать | Этап |
|---|---|---|
| G-HOST | Где прод: VPS или хостинг. Можно ли держать Node-процесс (pm2/systemd), версия Node | S00 |
| G-BX | Версия и редакция Битрикса, модули `catalog`, `sale`, обмен с 1С | S00 |
| G-DATA | Инфоблоки, свойства, ТП, типы цен, склады/остатки | S01 |
| G-AVAIL | Откуда 3 состояния наличия: в наличии / нет / уточните | S01 |
| G-LENS | Параметры контактных и очковых линз: свойства или ТП. В дизайне их выбора нет | S01 |
| G-COLOR | Цвета товара — отдельные товары или ТП | S01 |
| G-URL | Текущие URL, `urlrewrite`, SEO-поля, что сейчас в индексе | S02 |
| G-PAY | Онлайн-оплата: какая платёжная система | S01 |
| G-AUTH | Вход через VK, Mail.ru, Яндекс — нужен ли на старте | Николай |
| G-REVIEWS | Отзывы: свой инфоблок или внешний виджет (в макете `reviews-widget-wrap`) | S01 |

## 11. Явно отвергнуто

- Отдельный HTML для ботов по User-Agent (риск санкций за подмену контента).
- Nuxt: он хочет сам владеть роутингом, а роутинг у Битрикса.
- Рендер только в браузере: SEO.
- Цены и скидки, посчитанные на клиенте.
